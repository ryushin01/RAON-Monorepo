# 접근성·표준 점검표

KWCAG 2.2(KS X OT0003) 33개 검사항목을 RAON에 대조한 결과입니다. 항목과 기준은 [비공식 정리본](https://a11ykr.github.io/kwcag22/)을 근거로 했으므로 **인증이나 공식 인용에는 원문으로 다시 확인해야 합니다.** 전문 심사나 스크린리더 실사용 검증을 거친 결과가 아닙니다.

- **자동:** E2E나 단위 테스트가 검사합니다(`apps/web/e2e/standards.spec.ts`, `quality.spec.ts`).
- **코드 확인:** 코드를 읽어 확인했고 자동 검사는 없습니다.
- **해당 없음:** 현재 그런 콘텐츠나 기능이 없습니다. 추가할 때 다시 봅니다.

## 기능별 결정

- **메인 배너:** 자동으로 넘어가지 않고 버튼으로만 넘깁니다(5.4.2, 6.2.2).
- **별점과 회차 순서:** 라디오나 끌어 놓기 대신 버튼을 씁니다. 선택만으로 저장되지 않게 하고, 키보드와 단일 포인터로 쓸 수 있게 합니다(6.1.1, 6.5.1, 7.2.1).
- **표지 업로드:** 파일을 고르는 것만으로 올리지 않고 버튼을 눌러야 올립니다(7.2.1). 표지는 제목이 옆에 글자로 있어 장식으로 다룹니다(5.1.1).
- **뱃지:** 색이 아니라 글자로 표시합니다(5.4.1).

## 알려진 한계

- 스크린리더(센스리더, VoiceOver 등) 실사용 검증은 하지 않았습니다.
- 대각선 검사와 고정 영역 가림 검사는 대표 화면만 봅니다.
- 에디터 본문은 서식이 필요해 `contenteditable`에 `role="textbox"`를 씁니다(네이티브 `textarea`로 대체 불가). 키보드는 Tiptap이 처리합니다.
- html-validate의 나머지 지적은 표준 위반이 아닙니다. 불리언 속성 표기와 React의 `_r_` 형식 `id`, 숨겨진 화면 때문에 나오는 랜드마크 이름 경고입니다. CI에서는 돌지 않습니다.

## 숨겨진 화면 규칙

Next는 지나간 화면을 `display:none`으로 문서에 남깁니다([Activity](https://nextjs.org/docs/app/guides/preserving-ui-state)). 그래서 코드를 쓸 때 다음을 지킵니다.

- `<main>`을 직접 쓰지 않고 `shared/ui`의 `Main`을 씁니다.
- 고정된 `id`를 쓰지 않습니다. `useId`나 `aria-label`을 씁니다.
- 로그인과 로그아웃은 전체 새로고침으로 이동해 이전 사용자의 화면을 지웁니다.
- 새로 만드는 화면의 상태가 다음 방문에 남지 않게 합니다(새 회차는 초안을 먼저 만들고 그 주소로 이동).
